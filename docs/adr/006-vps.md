# ADR-006: VPS propia para todos los servicios de aplicación

**Date**: 2026-05-20  
**Status**: Accepted

## Context

Se necesita decidir dónde desplegar el frontend, el backend y el stack de observabilidad.

## Decision

Usar una **VPS de OVHcloud** para alojar todos los servicios de aplicación: frontend (static build), backend NestJS, y el stack completo de observabilidad (Prometheus, Grafana, Loki).

La base de datos (Aiven) y el CDN de audio (Cloudflare) se externalizan deliberadamente — ver ADR-004 y ADR-005.

## Rationale

- Control total sobre el entorno de despliegue — relevante para demostrar conocimientos de infraestructura en el TFM
- OVHcloud tiene datacenters en Europa — latencia baja para usuarios europeos y cumplimiento de GDPR
- Coste predecible y bajo frente a soluciones cloud (AWS, GCP, Azure)
- Docker Compose permite levantar y gestionar todos los servicios de forma reproducible
- El stack de observabilidad self-hosted (Prometheus + Grafana + Loki) es viable en una VPS sin coste adicional
- Demuestra capacidad de operar infraestructura real, no solo desarrollar código

## Alternatives Considered

- **Vercel + Railway**: más simple pero menos control y menos demostrable académicamente
- **AWS EC2 / DigitalOcean**: más caro o menos integrado con el ecosistema europeo

## Consequences

- Todos los servicios se orquestan con Docker Compose
- El despliegue se automatiza con GitHub Actions (CI/CD)
- La VPS necesita recursos suficientes para correr backend + observabilidad simultáneamente
- La DB y el CDN están fuera de la VPS para no saturarla
