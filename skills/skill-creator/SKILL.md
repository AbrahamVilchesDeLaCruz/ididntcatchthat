## When to Create a Skill

Create a skill when:
- A pattern is used repeatedly and the AI needs guidance
- Project-specific conventions differ from generic best practices
- Complex workflows need step-by-step instructions

**Don't create a skill when:**
- The pattern is trivial or self-explanatory
- It's a one-off task

> Lee `references/docs.md` para el spec completo de agentskills.io y la estructura de directorios esperada.

## Skill Structure

```
skills/{skill-name}/
├── SKILL.md        # Required — main skill file
└── assets/         # Optional — templates, examples
```

Skills live in `skills/` in the repo root. Never in `.claude/`, `.github/`, or `.opencode/` — those are generated by `skills/setup.sh`.

## Naming Conventions

| Type | Pattern | Example |
|------|---------|---------|
| Generic | `{technology}` | `nestjs`, `react` |
| Project-specific | `{project}-{component}` | `app-flashcard` |
| Workflow | `{action}-{target}` | `skill-creator`, `skill-sync` |

## After Creating a Skill

1. Add it to the **root `AGENTS.md`** Available Skills table:
   ```markdown
   | `{skill-name}` | {Description} | [SKILL.md](skills/{skill-name}/SKILL.md) |
   ```
2. Add auto-invoke row if applies (action → skill).
3. Add it to the relevant scope `AGENTS.md` (`apps/api/AGENTS.md` or `apps/client/AGENTS.md`).
4. Run `skills/setup.sh` to re-sync symlinks.
